# Architecture

> Package layout, directory map, and data flow for the DiCo-NLI project.

## Package

`src/dico_nli/` is the only Python package (distribution name `dico-nli` in `pyproject.toml`). It is empty apart from `__init__.py`. Every module under it is guarded by the tests-first hook (`testing.md`).

## Data flow

```
datasets/dico-nli/final_data/<track>/{train,dev}.csv          (ignored, cloned from the task repo)
        │  loader: phrase pair, label, instance_id, reverse_pair_id
        ▼
model   baseline: fine-tuned encoder (DeBERTa-v3-base, organizers' pilot)
        method:   decoder LLM with a consistency mechanism (A2 decides which)
        │  one label per instance
        ▼
predictions.csv  (instance_id,label)  under artifacts/<run>/
        │
        ▼
official scorer (evaluation_functions, from the task repo)
        → weighted F1, SoftCons, HardCons
        → promoted to experiments/<date>-<slug>/ with seed, config, command, data commit hash
```

Consistency is scored by pairing each instance with its reverse via `reverse_pair_id`; the model never sees that field.

Compute: CPU and Colab for the encoder baseline; Modal for anything larger (`commands.md`). The dev set is the course test set; model selection uses a held-out slice of train.

## Directory map

| Path | Holds | In git? |
|---|---|---|
| `src/dico_nli/` | Library code: data loading, baselines, the proposed method, evaluation glue | yes |
| `tests/{unit,integration,regression}/` | pytest tiers, see `testing.md` | yes |
| `experiments/` | One folder per run family: config, seed, command, data commit hash, and the promoted results that a report cites | yes |
| `datasets/` | Metadata, licence, split definitions, download instructions. Never raw data | metadata only |
| `artifacts/` | Raw run outputs, predictions, checkpoints, caches | no (gitignored) |
| `notebooks/` | Exploration and EDA only; anything a report depends on moves to `src/` or `experiments/` | yes, outputs stripped |
| `docs/deliverables/a{1,2,3}-*/` | What is handed in for each assignment | yes |
| `docs/research/` | Literature notes, reading log, related-work summaries | yes |
| `docs/paper/` | The A3 paper source and its figures | yes |
| `docs/governance/` | AI usage disclosure | yes |
| `scripts/` | Reusable tooling promoted from `.tmp/` (`readme/build_assets.py` generates the README panels) | yes |
| `assets/readme/` | The README's SVG panels, light and dark, regenerated by the script above and committed | yes |

## Where results live

A number that appears in a deliverable must trace to a folder under `experiments/` that records the seed, data commit hash, config, and the exact command. Raw outputs stay in `artifacts/`; the promoted summary (a table, a JSON of metrics, a figure saved as PDF) is committed next to its config.
