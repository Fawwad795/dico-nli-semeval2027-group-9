\section{Evaluation Setup}
\label{sec:evaluation}

\paragraph{Weighted F1.}
With $n_c$ gold instances of label $c$ among $N$ and $F_c$ the F1 of label $c$,
\begin{equation}
\text{wF1} = \sum_{c \in \mathcal{L}} \frac{n_c}{N} F_c, \qquad F_c = \frac{2 P_c R_c}{P_c + R_c}.
\end{equation}
Each label counts in proportion to its frequency, so \NO{}, 16\% of the data and the hardest class for every model, weighs least. Macro F1 averages $F_c$ with equal weights, and micro F1 equals accuracy for single-label prediction; we report macro F1 next to the official score so that a weak minority class stays visible.

\paragraph{Consistency.}
Let $\Rev$ map \EQ{} to \EQ{}, \FW{} to \BW{} and \BW{} to \FW{}; \NO{} has no reverse. Let $\mathcal{P}$ be the set of reversible pairs $(x, x^{r})$ in the development set ($|\mathcal{P}| = 277$), $f$ the system, $y$ the gold label and $\mathbb{I}[\cdot]$ the indicator:
\begingroup\small
\begin{align}
\SoftCons &= \frac{1}{|\mathcal{P}|} \sum_{\mathcal{P}} \mathbb{I}\big[f(x) = \Rev(f(x^{r}))\big], \\
\HardCons &= \frac{1}{|\mathcal{P}|} \sum_{\mathcal{P}} \mathbb{I}\big[f(x) = y \wedge f(x^{r}) = y^{r}\big].
\end{align}
\endgroup
Because gold labels obey the reversal, a pair that is right in both directions is also consistent, so $\HardCons \le \SoftCons$. Negative pairs have no reversed twin and enter only weighted F1; a \NO{} prediction on a reversible pair counts as incompatible.

\paragraph{What each score rewards.}
Weighted F1 rewards correct labels on single instances, \SoftCons{} rewards self-consistency whether or not it is correct, and \HardCons{} rewards correctness on whole pairs. The constant systems show why the task reports all three. Predicting \EQ{} everywhere is consistent on every pair, so it scores \SoftCons{} 1.000 with weighted F1 0.110, and its \HardCons{} of 0.314 is the share of reversible pairs whose gold label is \EQ{} (87 of 277). Predicting \NO{} everywhere scores 0.044, 0 and 0.

\paragraph{Protocol.}
Every score is computed by the official scorer, run unchanged as the competition platform runs it. The classical baselines are also cross-validated on the training data in five folds grouped by source pair, every fold scored by the same scorer. Each run records its seed, the data commit, the code commit and the exact command; \cref{app:runs} maps every number in this report to its run.
